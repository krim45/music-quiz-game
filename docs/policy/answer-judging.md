# 정답 판정 규칙

라운드 중 채팅 메시지가 현재 곡의 정답으로 인정되는 조건.

## 인정하는 답

곡의 **제목**과 **추가 정답** 각각에 대해, 아래 두 가지 중 하나와 같으면 정답이다.

1. 그 답 그대로
2. 그 답에서 **괄호 부분을 뺀 것** — `()`와 `[]`, 괄호 안의 괄호 포함

괄호 **안의 내용**은 따로 인정하지 않는다. 괄호 안이 다른 이름(`미쳐 (Crazy)`의 `Crazy`)이면
추가 정답에 넣어야 인정된다. `Hype Boy (Live)`의 `Live`처럼 곡 이름이 아닌 표기가
정답이 되는 걸 막기 위해서다.

## 같다고 보는 기준

비교 전에 양쪽을 이렇게 다듬는다.

1. 유니코드 NFKC 정규화 — 전각 문자(`ＤＮＡ`, `（`)를 보통 문자로
2. 소문자로
3. **문자와 숫자만 남긴다** — 띄어쓰기, 문장부호, 기호, 이모지는 모두 무시

다듬은 결과가 비면(특수문자로만 된 답, 예: `?!`) 띄어쓰기만 무시하고 비교한다.

## 예

| 답 | 입력 | 결과 |
|---|---|---|
| `It's You` | `its you` | 정답 |
| `O.O` | `oo` | 정답 |
| `이름이 뭐예요?` | `이름이뭐예요` | 정답 |
| `미쳐 (Crazy)` | `미쳐` | 정답 |
| `미쳐 (Crazy)` | `crazy` | 오답 — 추가 정답에 `Crazy`가 있어야 정답 |
| `BLUE CHECK (Feat. Jay Park, Jessi) (Prod. by Slom)` | `blue check` | 정답 |
| `Hype Boy (Live)` | `live` | 오답 |
| `좋은 날` | `좋은날씨` | 오답 — 부분 일치는 인정하지 않는다 |

## 구현

- 판정: `backend/src/utils/answer.ts` (`isAcceptedAnswer`) — 채점은 여기서만 한다.
- 복사본: `frontend/src/utils/answer.ts` — 곡 추가 화면에서 "이미 정답으로 인정되는 추가 정답"을 걸러내는 데만 쓴다.
  `@music-quiz/shared`가 타입 전용이라 런타임 코드를 공유하지 못해 두 곳에 있다. **규칙을 바꾸면 둘 다 고친다.**
- 사용자에게 규칙을 설명하는 문구: 게임 방법 모달, `/about`의 규칙·FAQ, 곡 추가 가이드.
